## 2. 拼豆仓

### 2.1 入库时记录价格

- **单个色号**（`components/stock/CodeSheet.tsx`）：原来要填「单价（元/颗）」，现在填「这次花了多少钱」，应用自己换算；加了「+500 / +1200 / +4000 颗一包」按钮和每千颗价格提示。
- **批量入库、到货入库**（`BatchEntry.tsx`、`pages/Shopping.tsx` 的 ReceiveSheet）：每行可单独填金额；同时填订单总价时，余额按颗数分摊到没填金额的行。行金额之和超过总价时显示提示，不会悄悄改数。粘贴文字可带价格（`A1 1200 ¥1.26`、`A1 1200 1.26元`）；数量后面的裸数字不当作价格。
- **套装初始化**（`KitInit.tsx`）：可填这套的总价，默认按 `lib/purchase.ts` 的报价带出。
- **补填价格**（`pages/History.tsx`）：给以前没有价格的入库批次补填或修改总价，可撤销。
- 金额计算在 `lib/pricing.ts`，全部用整数「分」，分摊用最大余数法，各行之和恒等于总价。数据模型没有变：`unitPrice` 仍是元/颗，没有新增同步集合。

### 2.2 补货预告

- `lib/forecast.ts`：按色号计算现有库存、计划图纸用量（含损耗）、已下单未到货数量、月均消耗、预计用完时间和建议购买量。
- 月均消耗取最近最多 6 个 30 天窗口的加权平均，越近权重越大；第一条记录之前的月份不计入。消耗记录少于 3 次时不估算，只按计划图纸预告，界面会说明。
- 建议购买量 = 计划用量 + 备货期内的常规消耗 − 库存 − 在途，再用现有的包装优化凑整（含 500 颗包满 10 包的规则）。
- 界面：数据洞察页的「补货预告」面板（1 / 2 / 3 个月备货期、复制补货清单）和总览页的卡片。
- 限制：预计花费固定按 1200 颗包 ¥1.26 计算，不跟随采购页的价格选择。

### 2.3 电脑端和手机端操作

- 新增快捷键（`lib/shortcuts.ts`）：`/` 聚焦搜索，`g` + 字母跳转页面，`?` 打开快捷键列表；格子编辑器和拼装模式的工具、撤销、换色、换板快捷键。输入框内、输入法组字时和带 Ctrl/Alt 的组合不触发。
- 修复：拼装模式点过任意按钮后方向键失效；多层弹层按一次 Esc 全部关闭（现在只关最上层，焦点回到触发按钮）。
- 格子编辑器：Ctrl+滚轮以光标为中心缩放，空格或中键拖动；双指手势现在同时平移和缩放。
- 拼装模式在桌面上不再限制在 520px 宽（最大 1180px）。

## 3. 拼豆图纸工坊

### 3.1 去背景

- 新的本地抠图引擎 `src/domain/matting.ts`（纯函数、类型化数组、Lab 色彩空间），界面在 `src/components/BackgroundMattingPanel.tsx`。
- 自动选择方式：纯色、双色、渐变背景走本地算法，不下载模型；复杂背景走 AI 模型。界面用一句话说明用了哪种方式和原因。模型加载失败（离线、被拦截）时改用本地方式并提示，不再报错。
- 本地算法的改进：边框背景色估计支持双色和渐变；容差随边框噪声和强度自适应；白/灰背景上的细缝（如手臂与身体之间）会去掉，较厚的浅色区域（眼白、白衣服）保留；柔和阴影当作背景；边缘毛边按强度清理；小碎块按最大连通块比例清理；主体颜色碰到图片边缘时不再被误当背景。
- 可调：保守 / 标准 / 强力，实时预览，原图 / 去背景后切换，点选去除、点选保留，撤销一步，还原，以及「只用本地快速方式」。
- `dropBorderWhite` 增加 `rimPasses` 选项（默认 1），清理边缘残留的近白豆子，签名兼容。
- 限制：边缘颜色没有做去污染，只是去掉毛边像素；整片浅灰主体配白背景在「标准」下可能被当成阴影（用「保守」或「点选保留」）；AI 模型路径不使用点选修正和强度设置。

### 3.2 电脑端和手机端操作

- Ctrl+V 粘贴图片；工具快捷键 V / B / G / I / E / M 不再要求先点中画布；`+` `-` `0` 缩放，`C` 切换格内色号，`?` 打开快捷键与手势说明。
- 缩放改为 50%–400% 连续；Ctrl+滚轮（和触控板捏合）以光标为中心缩放；查看模式左键拖动、任意模式中键拖动平移。
- 触摸：双指缩放和平移；第二根手指落下会取消刚开始的一笔。
- 重新生成图纸时，手工修改会进入撤销栈并提示「按 Ctrl+Z 可找回」，不再直接丢失。
- 相关逻辑在 `src/domain/viewGestures.ts`。没做：导出快捷键（Ctrl+S / Ctrl+E 属于浏览器）；空格拖动（空格在画布上是「上色」）。

### 4.1 同步

- **Hub 数据库被还原或替换**：Hub 现在有数据库标识（`epoch`，存在 `meta` 表并镜像到 `config.json`），`/api/sync` 返回 `epoch` 和 `maxSeq`。客户端发现标识变了或自己的游标超过 `maxSeq` 时，把游标清零并重新上传本地全部记录，再按原有的“最后写入胜出”合并，不删除任何一方的数据。新旧版本的 Hub 和客户端可以混用。
- **时钟**：所有写入在 `lib/db.ts` 统一打时间戳，不会低于已有值 + 1；客户端按 Hub 返回的时间估算偏差（≥ 2 秒才修正）。字段类型不变。
- **分块上传**：待上传记录按约 2 MB 或 400 条一块发送，每块确认后即移出，失败后从未确认的部分继续。单条超过 20 MB 的记录仍会失败。
- **图片校验**：下载的原图和缩略图核对 sha256，不一致重试一次，仍不一致则不保存。
- **备份导入**：逐条校验，坏记录跳过并说明数量和原因；不是备份文件的直接拒绝。
- 没有做的验证：没有用真实的 Hub 还原流程端到端演练，游标恢复由纯函数测试和一个 Hub 测试覆盖。已知局限：还原的数据库如果之后又增长到超过客户端游标，只有在 `config.json` 没有一起还原时才能发现。

### 4.2 已完成的图纸改回去

- 已完成且扣过库存的图纸改回收藏 / 计划拼 / 制作中时，会询问「把豆子放回库存」（默认）还是「保持已扣除」。两种选择都会让图纸回到采购清单和补货预告。
- 放回库存是新增的补偿流水（`refundOf` 指向原扣除记录，ID 确定，两台设备同时操作也只生成一份），原流水不改动；数量取自原扣除记录，不会重复退。图库的批量改状态同样支持。
- 被退回的扣除不再计入数据洞察的每月消耗和补货预告的消耗速度。
- 「标记完成」确认框现在会列出库存不够的色号。

### 4.3 包装价格统一

- 1200 颗包的价格（¥1.26 或 ¥1.50）成为一个同步的偏好 `prefs.price1200`，采购方案、采购清单和补货预告都用它；`?p1200=` 链接仍然有效。

### 4.4 识别

- “离群墨水”清理：被标记的格子如果墨迹像印刷的色号（高度、位置与多数一致，对比度够），或者清掉后会低于图例给出的数量，就保留。水印带、淡色碎片仍会被清掉。
- 表头区域高度改为 max(320, 图片高度的 30%)，约 1067 px 以内的图片行为不变。

演练发现并修复的三个缺陷：

1. 还原的旧数据库之后又增长到超过设备游标时，旧的“标识 + 游标超前”两种检查都发现不了。现在 Hub 在数据库里保存一串同步标记（`marks` 表），`/api/sync` 返回 `mark` / `markOk`，客户端下次带回；还原的旧库里没有这个标记，客户端就清零游标并重新上传。新旧版本兼容，缺少标记不会触发重置。
2. 令牌失效（401）后配对表单不出现：设备记录里还留着旧令牌。现在 401 时清掉令牌，地址、游标和数据保留。
3. 时钟慢的设备上“已有值 + 1”的时间戳被当成已校正而不再对齐 Hub 时间，导致它后做的修改输给更早的修改。`bumpStamp` 现在会把这种时间戳抬到 Hub 时间。

剩余弱点：设备刚推送成功、还没再次同步时做的还原，可能丢掉那一次推送；标记只对已经和新 Hub 同步过的设备有效。

### 6.4 拼豆图纸工坊：AI 抠图模型自托管

- `scripts/copy-bg-assets.mjs`（`postinstall` 和 `prebuild` 时运行）下载库厂商发布的 1.7.0 数据包（约 285 MB，SHA-256 `a44fdaf4…2d0df5` 写在脚本里并校验），只取 `isnet_fp16` 模型和 CPU 运行时共 29 个文件、95.4 MB，放进不进仓库的 `public/bg-model/`。下载失败只打印一行警告，应用按原来的方式工作。`BG_ASSETS_SKIP=1` 跳过（CI 已设置），`BG_ASSETS_FORCE=1` 强制重下。
- 应用启动抠图前探测本地清单，存在就把 `publicPath` 指向自身；否则沿用库的默认地址。Service Worker 不预缓存这个目录，首次使用后按 CacheFirst 缓存。
- 验证：图纸工坊 `tsc` 通过，vitest 296 项通过；带 `SMOKE_MODEL=1` 的浏览器冒烟通过，抠图过程中 32 个请求全部发往本机预览地址，没有任何外部请求，用时 14.7 秒。冒烟现在遇到任何外部请求都会失败。
- 没验证：首次使用后断网再用（Service Worker 缓存已配置但没实测）；脚本的下载失败路径。分发模型文件前请查看 `public/bg-model/LICENSE.md` 的条款。

## 7. 第五批（2026-11-16 当天）：按库存颜色管理

起因：入库了 MARD 221 色套装（A B C D E F G H M 九个系列），希望图纸和选色都围绕手里管理的色号。

“我管理的色号”= 所选套装里的色号 + 套装外但库存里有货的色号（`lib/palette.ts` 的 `managedCodes`）。套装里暂时用完的颜色仍算在内：用完了是去补货，不是换成别的颜色。

- **已保存的图纸按库存换色**（`lib/recolor.ts`、`components/pattern/StockRecolor.tsx`）：
  - 图纸详情页在用到范围外的颜色时出现卡片，弹层里列出每个颜色换成哪个最接近的色号（CIEDE2000）和差别程度，可选“我的套装和库存”或“只用现在有货的”，确认后才改；总颗数不变。
  - 图库顶部提示有多少张受影响，可“全部按库存换色”。已完成或已扣库存的不换；拼装进行中的在批量里跳过，可在详情页单独换（已拼的格子换到新色号上仍算已拼）。
  - 换色时用新颜色重画图片：只要图纸存了格子就画，包括原来只有截图的识别图纸，图库缩略图跟着变。只有用量、没有格子的图纸画不了。
  - 原样存在图纸的 `stockRecolor` 字段里（用量、格子、预览图、已核对状态），随时“恢复原色”；第二次换色保留最初的原样。旧版本会忽略这个字段。
- **选色只列我管理的色号**（`lib/managed.ts`）：入库选色、格子编辑的画笔、识别结果的色号列表默认先列管理的色号，套装外的仍能搜到并带“套装外”标记；手动录入遇到套装外色号时给出提示。生成图纸的“只用库存里有的颜色”按设备记住上次的选择，并显示这次会用到几种颜色。
- **下一张拼什么**（`lib/nextUp.ts`、`components/insights/NextUp*.tsx`）：数据洞察页在“现在能拼什么”下面给出排行，总览页有一张只显示第一名的卡片。富余 = 库存 − 制作中占用 − 最低库存线。排序依次看：能否不缺豆拼完、用量里多大比例来自富余的颜色、拼完会把几种颜色压到偏少；每条带一句理由。“就拼这张”只跳到图纸，不改状态。
- **库存导出**：库存页“导出库存 CSV”（色号、颜色、HEX、颗数，只含有货的色号）。
- **拼豆图纸工坊**：新增“从拼豆仓导入库存”（读上面的 CSV，替换已登记库存并打开“只用我手头有的颜色”），纯本地读文件，不连任何服务器。线上版本默认不显示这个入口，构建时设 `VITE_HUB_LINK=1` 才打开。
- 验证：拼豆仓 `tsc` 通过、vitest 599 项、服务端测试通过、浏览器冒烟全部通过且 0 个控制台错误（新增一步：套装外提示 → 换色预览 → 确认 → 恢复 → 图库批量换色 → 导出按钮 → 下一张拼什么）；图纸工坊 `tsc` 通过、vitest 298 项、冒烟通过。
- 没验证：带格子的识别图纸换色后重画图片这条路径没有浏览器步骤覆盖（冒烟里换色的是手动录入的图纸，没有格子）；新界面没有在真机上看过。
