## 2. 修复的问题

### 2.1 服务端与安全（`server/hub.mjs`）

- `/api/local-token` 可被局域网内用浏览器打开的任意网页读取，导致 token 与配对码泄露（CORS 原样回显 Origin）。现在要求回环地址的 socket、回环 Host 头，且 Origin 为空或为回环地址；同时阻止 DNS 重绑定。
- 静态文件路由使用 `startsWith(DIST_DIR)`，兄弟目录（如 `dist-old`）可被访问。现在要求路径分隔符。
- 畸形的 percent 编码原先返回 500，现在返回 400。
- 文件在流式传输时被删除会导致 Hub 进程崩溃，现已处理流错误。
- `/api/pair` 未鉴权即可接收 20 MB 请求体，现限制为 4 KB。
- Blob 临时文件名增加随机后缀。

### 2.2 识别引擎（`web/src/lib/recognize/`）

- 图例色块只有 B 系列编号（如 “B13”）时被读成豆数（813）。现在仅含编号的标记不再作为计数。
- 图例中存在但网格上豆数为 0 的颜色仍可能得到 100% 置信度，现上限为 99%。
- “容差内”规则（较大值的 3%，且至少 2 颗）原有三处重复实现，现合并为共享函数 `countsNear`。
- 取消一个 OCR 任务会终止所有池化 worker，现只终止被取消任务对应的 worker。

### 2.3 拼豆仓客户端

- 采购方案忽略已有库存（新增 `needAfterStock`）。
- 损耗取整多买一颗（100 颗 + 10% 得到 111），现使用共享函数 `withLoss`。
- 库存大于 0 时“整包多出”计算错误。
- 已应用的方案会再次应用并覆盖手动修改的数量。
- 批量入库粘贴 “A12” 被解析为 A1×2（“H19” 解析为 H1×9）。现在必须有分隔符或空格。**行为变化：** 类似 “A1500” 的连写形式现在会被拒绝。
- 库存恰好为 0 的颜色从不提示低库存。
- 批量录入的名称无法清空，输入时会丢失空格。
- 份数允许输入小数，现已禁止。
- 重新识别会静默丢弃手动编辑的格子，现会先询问。
- 选择图片后添加图纸页面出现 React Hook 顺序错误（#310）。Hook 被放在 `RecognizePanel.tsx` 的提前返回之后；该问题是本轮迭代中引入的，由浏览器冒烟发现并已修复。

### 2.4 根应用“拼豆图纸工坊”（`src/`）

- 草稿/工程文件中 `boardTilePins` 小于 1 时，每次刷新标签页都会永久卡死。
- 草稿保存在 localStorage 已满时仍显示“已保存”。
- 保存第 7 个草稿时会静默删除最旧的草稿，现会询问并写明名称。
- Floyd–Steinberg 抖动修改了共享的采样网格，导致开启抖动时“像素化”对比错误。
- 文本下载在创建后立即释放 URL，Safari 下得到空文件；CSV 有两个 BOM。
- 点击复选框或滑块后，撤销/重做快捷键失效。
- 平滑处理使用调色板索引的中位数（调色板按色号排序而非亮度），可能选出奇怪的颜色；现改为多数投票。
- 自定义尺寸输入框每次按键都会重新生成。

## 3. 新功能

### 3.1 拼豆仓

| 功能 | 入口 | 说明 |
| --- | --- | --- |
| 图库图纸编辑 | 图纸详情 → 编辑格子 | 橡皮可单点或拖动批量清除假豆子；画笔可改色号；支持取色、整色替换/删除、撤销/重做；按格子重算用量。保存后用量更新，状态变为“未核对”，并记录“已手动修改 N 格” |
| 格子显示色号 | 图纸矩阵工具栏 → 显示色号 | 每格 ≥14px 时在格内画出色号；格子太小时提示“放大后显示色号”；开关状态会记住 |
| 采购方案推荐 | `#/purchase` | 推荐组合卡片（含推荐理由）；“最省钱”/“最少浪费”标签；推荐依据可选 综合 / 最省钱 / 最少剩余；每个方案包含补充包明细（色号、规格 4000/1200/500、包数、买到、需要、剩余、小计）；支持复制采购清单。装包时若价差很小（≤ max(¥0.30, 3%)）优先少剩余；500 颗包不足 10 包时自动改用其他规格，或补足到 10 包 |
| 下单快照 | 采购清单 / 采购方案 → 复制 | 复制时记录下单清单；到货入库默认按当时的下单清单 |
| 数据洞察 | `#/insights` | 现在能拼什么（按库存覆盖率排序，缺色时给出 ΔE≤6 的替代色建议）；最缺的颜色 Top 15；色系分布；库存健康（充足 / 吃紧 / 闲置）；进出趋势；识别质量 |
| 拼装模式 | 图纸详情 → 开始拼（`#/build/<id>`） | 全屏；按板（29 / 52 / 58 / 整图）分块，板内按颜色从多到少逐色拼；只高亮当前颜色并标注色号；支持按行模式与撤销；进度随图纸同步保存，重新打开可继续；拼装中不扣库存，全部完成后进入“标记完成” |

## 5. 已知限制

- 数据洞察中的“每月完成”由库存扣减记录估算，因为图纸没有完成时间戳；花费只统计有单价的采购。
- 拼装模式：两台设备同时拼同一图纸时，最后写入者生效；撤销栈在刷新后不保留。
- 图纸编辑器未拦截浏览器的后退按钮（应用内链接与关闭标签页已拦截）。
- 500 颗包补货时，多出的包会放在第一个已使用 500 颗包的颜色上。
- 识别校对视图仍有自己的内联编辑器，后续可改用共享的 `MatrixEditor`。

## 6. 待办（未实现）

同步与数据：

- 客户端游标超前于被还原的 Hub 数据库时，不会被修复。
- 同步的“最后写入胜出”依赖本地时钟，且部分写入方未使用 max(已有值+1)。
- 整个 outbox 在一个请求中发送（上限 20 MB）。
- 图纸在标记“完成”后被重新打开，会从采购清单中消失，且库存不会退回。
- 下载的 blob 在客户端不做哈希校验。
- 备份导入只做浅层校验。

识别引擎：

- “离群墨水”清理可能误删真实的少数近白色豆子（需要评估数据后再改）。
- 表头区域只从顶部 320px 裁剪。
- 图例中编号重复时保留较大的计数。

根应用“拼豆图纸工坊”：

- 取消 worker 后，排队中的转换不会停止。
- 转换输入变化时，手动编辑会丢失。
- 构建进度的 key 是矩阵的哈希值。
- 背景去除模型从第三方 CDN 获取，但 README 写的是离线可用。

产品想法：

- 在途订单。
- 可打印的分板 PDF。
- 快速核对的滑动模式。
- 完工记录。
- 卖家资料。
